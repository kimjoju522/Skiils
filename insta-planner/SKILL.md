# insta-planner

키워드 하나로 인스타그램 게시물 한 편을 **기획 → 문구 → 디자인 → 캡션 → 업로드 점검**까지 끝내도록 돕는 스킬.

## 가장 중요한 원칙

- **references는 기본 가이드일 뿐 한계가 아니다.** 파일에 없는 분야, 유형, 색상도 다룬다. 키워드의 분야에 맞게 판단해서 확장한다.
- **키워드별 정보는 조사해서 쓴다.** 트렌드, 인기 주제, 검색 의도, 관련 해시태그는 웹 검색 도구가 있으면 검색해서 근거로 삼는다. 검색을 못 하는 환경이면 일반 지식으로 하되, "최신 트렌드는 직접 확인이 필요하다"고 한 줄로 알린다. 이때 트렌드 모드는 **출처 없는 일반적인 방향만**, 수치·날짜·제품명 없이 "출처 없음"으로 표시해서 답한다.
- **사실은 지어내지 않는다.** 제품 효능, 통계, 가격, 날짜, 조리 시간·분량 같은 수치는 조사로 확인된 것만 쓴다. (직접 해 본 값이 아닌 시간·분량은 "확인 필요"로 표시한다.) 확인 못 한 건 "확인 필요"로 표시한다. 사용자가 써 보지 않은 제품의 후기를 쓰지 않는다.
- **사용자가 결정할 곳에서만 멈춘다.** 멈추는 곳은 ① 분야를 전혀 모를 때의 분야 질문(트렌드 모드. 분야를 일부라도 알면 묻지 않는다), ② 주제 선택(트렌드 번호 고르기, 제품 큐레이션의 "제품·이미지 사용 확인" 포함), ③ 포인트 색상 선택, ④ Canva 수정 저장(`commit`) 승인, ⑤ 마지막의 프로필 저장 질문, 이 다섯 가지뿐이다. **한 메시지에는 질문을 하나만** 둔다(⑤에서 "예"라고 답한 뒤의 온보딩 질문만 번호를 매긴 한 메시지로 묻는다). 나머지(기획서, 문구, 캡션 등)는 제안하고 멈추지 않고 진행한다. 사용자가 "알아서 해줘"라고 했거나 질문에 답할 수 없는 환경이면 ①은 "분야 전반"으로 가정하고, ②③은 1순위 안으로 정하고(제품 큐레이션이면 제품 목록은 그대로 진행하고, 승인받지 못한 이미지는 쓰지 않고 컬러 칩이나 글자 중심으로 대체한다), ④는 저장하지 않고 취소한 뒤 어긋난 목록만 알리고, ⑤는 건너뛴다. 어떻게 처리했는지 알린다.
- **색은 항상 실제 색으로 보여 준다.** 포인트 색상을 추천할 때뿐 아니라 트렌드 컬러, 제품 색, 디자인 수정안처럼 색을 말하는 모든 곳에서 HEX 숫자만 적지 않고 **실제 색 견본을 함께** 보여 준다. 방법과 폴백은 5단계의 "색은 HEX 숫자만 적지 말고 실제 색으로 보여 준다"를 따른다. 제품·트렌드 색은 정확한 값을 알 수 없으면 가장 가까운 색을 골라 "근사색"이라고 표시하고, 정확한 값처럼 쓰지 않는다.
- 대화는 한국어로, 짧고 구체적으로 한다. 전문 용어는 풀어서 쓴다.

## 0단계: 계정 정보 확인

1. 이 스킬 폴더의 `profile.md`가 있으면 읽는다. (계정 분야, 주제 비율, 타깃, 목표, 말투, 디자인 취향(제품 사진 처리 방식 포함), 시리즈, 이미 올린 게시물, 제작 완료·업로드 전 목록, 대외활동 규칙)
2. 없으면(처음 쓰는 사용자) **기획을 막는 질문은 하지 않는다.** 키워드가 있으면 바로 조사와 주제 추천을 시작하고, 모르는 항목은 기본값으로 진행한다. 계정 정보 정리(온보딩)는 **마지막 8단계 끝에서** 한다. (저장 여부를 먼저 묻고, "예"라고 하면 질문을 한 메시지로 묻는다.)
   - 기본값: 타깃 20대, 말투 친근한 존댓말, 이모지 조금, 카드 6~8장(유형이 정해지면 `references/post-types.md`의 유형별 장수가 우선)
   - 온보딩 질문은 **최대 4개**이고 이 순서다: ① 분야와 계정 한 줄 소개 ② 타깃 ③ 말투와 이모지 ④ 목표(저장·공유·팔로우·댓글·활동 포트폴리오 중). 이미 대화에서 알게 된 것은 묻지 않는다. 답을 받으면 `profile.template.md`를 바탕으로 `profile.md`를 만들고 나머지 칸은 비워 둔다. 스킬 폴더에 쓸 수 없으면 사용자의 작업 폴더에 만들고 어디에 만들었는지 알린다.
3. 키워드가 없어도 막지 않는다. 요청이 "요즘 트렌드/유행이 뭐야?"처럼 **트렌드 질문**이거나 "요즘 유행에 맞춰서 주제 추천해줘"처럼 **트렌드 기반 추천**이면 아래 **트렌드 모드**로 간다. `profile.md`의 주력 분야(예: 뷰티)를 범위로 삼고, 분야를 모르면 그때만 "어떤 분야 트렌드가 궁금해요?"라고 한 번 묻는다. 프로필이 없으면 **이 질문 하나만** 먼저 하고 온보딩은 하지 않는다. 프로필 정리는 게시물을 끝까지 만든 뒤 8단계 끝에서 한다.
4. 요청이 "○○ 브랜드들과 상품을 가져와서/모아서 게시물 만들어줘"처럼 **특정 제품군의 브랜드·제품 정보와 이미지를 모으는 것**이면(분야 불문. 예: "○○ 브랜드 신제품 소개", "에어프라이어 브랜드 비교", "겨울 핸드크림 제품 모아줘", 브랜드 한 곳의 제품 소개나 여러 브랜드 비교 모두 포함) 아래 **제품 큐레이션 모드**로 간다. 주제가 요청에 이미 있으므로 2단계의 주제 5개 추천은 건너뛴다.

## 트렌드 모드 (키워드 없이 트렌드를 물을 때)

1. 범위를 정한다: `profile.md`의 분야 + 사용자가 말한 범위(예: "뷰티", "겨울"). 오늘 날짜의 시즌을 반영한다.
2. 아래 "리서치 출처" 순서로 조사한다. 검색은 서로 다른 각도로 3~5회: 올해/이번 시즌 트렌드, 해외 vs 국내 흐름, 인기 색상·제품·콘셉트, 사람들이 많이 묻는 질문.
3. **트렌드는 최대 5개**(혼합 항목 포함)를 정리한다. 근거가 부족하면 3~4개로 줄인다.
   ```
   1. 트렌드 이름: 한 줄 설명
      - 근거: [매체명, 날짜](URL)
      - 게시물로 만들 때 각도: 한 줄
   ```
   목록의 **각 트렌드에는 원문을 연 출처가 최소 1건** 있어야 한다. 원문을 열지 못한 것은 목록에서 빼고, 끝에 "참고: ○○ (검색 요약만 확인)"으로 한 줄만 적는다. (이 참고 항목은 5개에 세지 않는다.) 6개월을 넘은 출처만 있는 트렌드도 목록에서 빼거나 "당시 전망"으로 분명히 표시한다.
   **페이지를 열 수 없거나 검색 도구가 없는 환경**에서는 위 조건을 적용하지 않는다. 이때는 항목을 3개 이하로 하고, 근거 줄은 "매체명 (검색 요약만 확인)" 또는 "출처 없음"으로 쓰며, 수치·날짜·제품명은 넣지 않는다.
4. 트렌드가 서로 엇갈리면 숨기지 말고 "매체마다 의견이 갈린다"고 밝힌다.
5. **분야 비율을 반영한다.** `profile.md`에 주제 비율이 있으면(예: 주력 분야 50% / 일상 50%) 트렌드도 그 비율에 가깝게 섞는다. 5개 안팎에서는 **2:3 또는 3:2도 허용**하고, 어느 쪽을 3개로 할지는 사용자가 물은 범위에 맞춘다. 주력 분야와 일상이 섞인 항목은 1개까지 "혼합"으로 둘 수 있다. 주력 분야 밖의 항목은 제품 트렌드가 아니라 **콘텐츠 형식·소재 트렌드**(예: 카드뉴스와 릴스 병행, 크리에이터·활동 일상 기록 포맷, 브이로그 소재)로 넣는다. 이것도 조사한 근거가 있을 때만 쓰고, 근거가 없으면 비율을 못 맞춰도 채우지 않는다.
6. **분량을 조절한다.**
   - **질문만 한 경우**("트렌드가 뭐야?"): 위 형식대로 답한다. 트렌드는 최대 5개, 항목당 **근거 포함 3줄 이내**로 쓴다. 그다음 "조사 범위" 한 줄(인스타그램을 못 봤다는 알림 포함)을 붙이고, 마지막에 "이 중 하나로 게시물을 만들까요? 번호를 알려 주세요."라고 묻고 멈춘다. (질문은 맨 끝에 하나만 한다. 프로필 저장 질문은 여기서 하지 않는다.)
   - **추천을 요청한 경우**("트렌드에 맞춰 주제 추천"): 트렌드는 **한 줄 요약 + 출처 링크**로 줄이고(각도 줄은 빼고), 바로 2단계로 이어서 **트렌드 전체에서 주제 5개로 묶어** 제안한다. 같은 말을 두 번 쓰지 않는다.
7. **번호를 고른 뒤**(질문만 한 경우): 그 트렌드의 "각도"를 주제로 확정하고 **2단계를 건너뛰어 3단계로 간다.** 주제를 더 다양하게 보고 싶다고 하면 그 트렌드로 2단계를 진행한다. (이 번호 고르기가 멈춤 ②에 해당하므로 주제를 또 묻지 않는다.)

## 제품 큐레이션 모드 (브랜드·상품을 가져와서 게시물을 만들 때)

요청 예: "겨울에 딥플럼 색상의 글로스 틴트 브랜드들과 상품을 가져와서 게시물 만들어줘", "올겨울 쿨톤 블러셔 제품 모아서 카드뉴스 만들어줘". 브랜드, 제품명, 가격, 이미지가 들어가는 게시물이다.

1. **조건 정리** (되묻지 않고 정한다): 제품군, 색·용도·가격대 같은 조건(예: 딥플럼, 자취용, 2만 원 이하), 시즌, 개수(기본 4개, 3~5개), 지역(기본은 한국에서 살 수 있는 것). 브랜드를 지정했으면 그 브랜드의 제품으로 한다. 요청에 있는 조건은 그대로 따르고, `profile.md`의 타깃과 말투를 쓴다.
2. **후보 찾기**: 웹 검색(브랜드 공식몰, 올리브영·화해 같은 판매·리뷰 사이트, 분야 매체)으로 후보를 8~10개 찾고, 요청한 색에 가장 맞고 **지금 살 수 있는** 4개 안팎으로 줄인다. 사용자가 브랜드를 지정하지 않았다면 한 브랜드에 몰리지 않게 **서로 다른 브랜드**로 고른다. 조사와 페이지 열기는 **직접** 한다. 검색 도구가 없는 하위 에이전트에게 맡기면 제품 주소를 만들지 못해 실패한다(작성 시점에 그런 일이 있었다).
3. **제품 정보 확인 (필수)**: 고른 제품마다 **원문 페이지(브랜드 공식 페이지 또는 판매 페이지)를 열어서** 아래를 확인한 것만 쓴다. 열지 못한 제품은 목록에서 뺀다. 페이지를 열 수 있는 도구가 전혀 없는 환경이면 카드를 만들지 않고, 검색 요약으로 본 후보를 "확인 필요" 목록으로만 알리며 제품 페이지 주소를 주시면 이어서 만들 수 있다고 안내한다.
   - 페이지는 웹 읽기 도구로 열고, 막히면(403, 빈 화면) **브라우저 도구**로 연다. 한 판매처가 막히면(올리브영은 막히거나 비어 보일 수 있다) 브랜드 공식몰, 마켓컬리, 11번가, W컨셉, 면세점 같은 **다른 판매처**로 바꾼다. 후기 사이트(글로우픽 등)는 제품 존재와 분류를 확인하는 보조 근거로만 쓴다. 화해 같은 앱이나 해외 쇼핑몰의 상품 정보(용량, 정가)는 판매 페이지를 열 수 없을 때 대체 근거로 쓸 수 있되 "판매 페이지 가격이 아님"이라고 표시한다. 외화 가격은 원화로 환산하지 않고 "해외 판매가 ○○ (한국 가격 확인 필요)"처럼 원문 통화 그대로 적는다.
   - 브랜드, 제품명, 컬러명(번호), 용량, 가격과 **확인한 날짜**, 구매처 링크, 판매 중인지(품절·단종)
   - **색 조건 적합도**: 요청한 색(예: 딥플럼)에 맞는지 컬러명, 공식 설명, 옵션 이미지 중 **2가지 이상**이 일치할 때만 고른다. 한 가지만 맞으면 "컬러 확인 필요"로 표시하거나 뺀다. 조건에 맞는 제품이 모자라면 3개로 줄여도 된다. 사진을 직접 넣어서 옵션 이미지를 모으지 않는 경우에는 컬러명과 공식 설명 **둘 다** 일치해야 한다.
   - 공식 설명의 특징(지속력, 광택 등)은 "공식 설명에 따르면 ~"으로 쓴다. 써 본 적 없는 제품의 발색·지속력을 경험처럼 쓰지 않는다.
   - 가격은 바뀔 수 있으니 카드와 캡션에 "○월 ○일 확인 기준"을 적는다. 카드의 제품명은 20자 안팎으로 줄여 쓰고(전체 이름은 캡션에), 가격 줄은 짧게 쓴다.
   - 컬러 칩은 제품 사진과 공식 설명을 보고 정한 **근사색**이다. 카드에 "실제 색과 다를 수 있음"을 작게 적는다. 색이 의미 없는 제품(가전, 식품 등)은 컬러 칩을 쓰지 않고 이미지를 쓰며, 이미지가 없으면 글자 중심으로 만든다.
4. **이미지 후보 모으기 (직접 한다)**: 먼저 **사진 처리 방식**을 정한다. `profile.md`의 "제품 사진"이 "직접 넣음"이거나 사용자가 "사진은 내가 넣을게"라고 했으면 **이 제품 큐레이션의 4번과 5번의 이미지 부분을 건너뛰고**, 제품 카드에 **사진 자리**만 만든다(아래 6단계, 결과를 알릴 때 사진 넣는 법을 안내한다). 그렇지 않으면 이어서 제품마다 이미지의 **출처 페이지와 이미지 주소**를 찾는다. 이 단계에서는 내려받거나 올리지 않는다.
   - **방법**: 제품 페이지를 **브라우저 도구로 열고**(내장 브라우저나 Chrome 확장), 페이지의 `og:image` 메타 태그, 큰 상품 이미지(`img` 중 가로 300px 이상인 대표 이미지), 브랜드 로고(브랜드명이 `alt`인 이미지)의 주소를 읽는다. 작성 시점에 마켓컬리 상품 페이지에서 이 방식으로 대표 이미지와 브랜드 로고의 공개 주소를 읽을 수 있었다(사이트와 환경에 따라 다를 수 있다). 읽은 주소가 `https://`로 시작하는 **공개 주소**인지 확인한다.
   - 컬러 선택형 상품(예: "23종 택1")은 대표 이미지가 **다른 컬러이거나 전 컬러 모음**일 수 있다. 상품 옵션(컬러 선택)을 눌러 그 컬러의 이미지나 스와치 이미지를 찾아보고(`references/photo-guide.md`), 해당 컬러와 맞는지 확인한다. 안 맞으면 그 제품은 컬러 칩으로 대체하고, 사용자에게 직접 찍은 사진을 부탁하는 안내문(`photo-guide.md`)을 함께 준다. 안내만 하고 멈추지 않으며, 사진이 오면 그때 넣는다.
   - 이미지 사용 허락 문구(브랜드 보도자료 페이지, 약관, 푸터)를 찾아 기록한다. 후기 사이트의 이용자 사진과 인플루언서 사진은 쓰지 않는다. 로고는 상표이므로 사용자가 요청했을 때만 넣는다.
   - 제품 이미지의 저작권은 보통 브랜드나 판매처에 있다. 사용 순서는 ① 사용자가 직접 찍은 사진 ② 브랜드가 보도자료·소개용으로 허용한 이미지(허용 문구를 원문에서 확인) ③ 그 밖의 공식몰·판매처 이미지(사용 허락이 필요할 수 있다고 알린다)이다. **제품 큐레이션 요청은 이미지 포함이 기본이다**(요청에 "이미지"라는 말이 없어도 브랜드·상품을 가져오라는 것은 제품 사진까지 포함한다. 로고는 사용자가 요청했을 때만 넣고, HTML 카드에는 로고 칸이 없어 브랜드 이름을 글자로 쓴다). 이미지를 쓰겠다는 의사로 보고, 아래 확인 질문에서 출처만 확인받는다. **컬러 칩 대체를 먼저 권하지 않는다.** 이미지가 해당 컬러와 맞지 않거나 못 구한 제품만 컬러 칩으로 대체한다.
   - **이미 만든 게시물**에 "브랜드 로고와 상품 사진도 넣어줘"라고 요청한 경우에도 같은 방법으로 이 모드의 4~5번을 거치고, 본문 6단계의 `edit-design`으로 기존 디자인에 넣는다.
5. **확인 질문 (멈춤 ②)**: 고른 제품 목록(브랜드·제품·컬러·가격·확인일), 이미지 후보의 출처, 저작권 안내를 **한 메시지**로 보여 주고 "이 제품들과 이미지로 진행할까요?" 하나만 묻는다. (이미지를 쓰는 것이 기본안이고, 이미지를 못 구한 제품은 컬러 칩으로 대체한다고 같이 적는다. 사진을 사용자가 직접 넣는 경우에는 이미지 항목 없이 제품 목록만 확인받는다.) 내려받을 파일이 있으면 출처와 개수를 함께 적는다. 사용자가 승인하면 **바로** 내려받거나 Canva에 올려 게시물에 넣는다. 이미지를 쓰지 말라고 하거나 답할 수 없는 환경("알아서 해줘" 포함)이면 제품 목록은 그대로 진행하고, 승인받지 못한 이미지는 쓰지 않고 컬러 칩(색이 의미 없는 제품은 글자 중심)으로 만든 뒤 그렇게 했다고 알린다. 같은 메시지에 컬러 근사색 견본과 "조사 범위" 한 줄을 함께 보여 줘도 되지만 질문은 하나만 한다.
6. **구성**: 리스트형으로 짠다. 표지 → 제품 카드(제품마다 1장: 이미지 또는 사진 자리·컬러 칩, 브랜드, 제품명, 컬러명, 가격·확인일, 공식 설명 한 줄) → 한눈에 비교(`list` 카드 1장, 항목마다 "브랜드 · 컬러 · 가격" 한 줄) → 고르는 팁 → 마무리(행동 하나). 제품 4개면 7~8장이다.
7. **색과 제작**: 이 6번의 구성이 본문 3단계 기획서를 대신하고, 4단계 문구는 그대로 쓴 뒤 본문의 5단계(디자인 방향)로 이어간다. 계정 고유 색이 있으면 1안은 그 색이고, 제품 컬러에서 뽑은 포인트 색은 다음 안으로 제안한다. 실제 색 견본을 보여 준다. 본문 6단계에서 이미지를 넣는 방법은 "제품 이미지 넣기"를 따른다.
8. **캡션·점검**: 협찬이나 제공받은 제품이면 광고 표기를 하고, 직접 산 제품이 아니면 "내돈내산"이라고 쓰지 않는다. 가격 기준일, 이미지 출처와 사용 허락, "1위", "최고" 같은 우열 단정이 없는지 `references/checklist.md`의 제품 항목으로 점검한다. 캡션에는 제품 구매 링크와 가격 기준일을 넣는다.

## 리서치 출처 (1단계, 트렌드 모드, 제품 큐레이션 모드 공통)

우선순위대로 시도하고, **실제로 확인한 것만** 근거로 쓴다.

1. **웹 검색**: 분야 전문 매체, 브랜드 공식 페이지, 뉴스, 블로그. 가장 안정적이므로 기본으로 한다.
2. **SNS·인스타그램의 공개 정보**: 웹 검색 결과에 잡히는 공개 게시물, 해시태그 페이지, 크리에이터 소개 글을 본다. 브라우저 도구나 페이지 읽기 도구가 있으면 **공개로 열리는 페이지**는 직접 열어 볼 수 있다. 로그인 창이 뜰 가능성이 높으므로 **시도는 1회만** 하고, 로그인 창이면 바로 시도를 멈춘다.
   - **1회**는 해시태그 페이지나 프로필 URL 중 한 곳을 한 번 여는 것이다. 실패해도 다른 URL로 재시도하지 않는다. 이 시도는 검색 횟수에 포함하지 않는다.
   - 아래 중 하나면 **로그인 벽**으로 본다: 로그인·가입 창이 뜸 / 로그인을 요구하는 문구가 보임 / 페이지 내용이 거의 비어 있음. 판단이 애매하면 로그인 벽으로 보고 "내용이 확인되지 않았다"고 쓴다.
   - 인스타그램은 로그인 없이는 게시물 일부만 보이거나 로그인 창이 나온다. 이 경우 더 시도하지 않고 **나머지 조사를 이어가며**, 결과에 "로그인이 필요해서 인스타그램 직접 조사는 못 했다"고 알린다. 사용자에게 되묻지 않는다.
   - 사용자의 계정 정보(아이디·비밀번호)를 묻거나 입력하지 않는다. 사용자가 로그인해 둔 브라우저 화면을 대신 보는 것도 사용자가 먼저 요청하지 않으면 하지 않는다.
3. **확인하지 못한 것은 확인하지 못했다고 쓴다.** "인스타에서 인기" 같은 말은 직접 본 근거가 없으면 쓰지 않는다. 좋아요·조회수 같은 수치를 지어내지 않는다.
4. **최신성 확인.** 오늘 날짜를 기준으로 삼는다.
   - 검색어에 올해와 이번 달(또는 시즌)을 넣어서 최근 자료를 먼저 찾는다.
   - 근거로 쓰는 기사는 **발행 시점을 적는다.** 날짜를 알 수 없으면 "날짜 확인 필요"라고 쓴다.
   - **검색 요약이 준 날짜는 틀릴 수 있다.** (요약에는 2026년이라 했는데 원문은 2024년이었던 적이 있다.) 날짜는 **원문 페이지에서 확인한 것만 확정**하고, 요약에서만 본 날짜는 "날짜 확인 필요"로 쓴다.
   - 발행 후 **6개월이 지난 자료**는 "지금의 유행"이 아니라 "당시 전망"으로 표시한다.
   - **최근 자료가 부족하면 채우지 않는다.** 원문에서 날짜를 확인한 **최근 6개월 안 자료가 2건 미만**이면(날짜 확인 필요인 것은 세지 않는다) 답변 맨 앞에 "최신 자료가 부족하다"고 밝히고, 오래된 자료는 "당시 전망"으로만 쓰고 핵심 근거로 삼지 않는다. 항목은 3~4개로 줄여도 된다. 페이지를 열 수 없는 환경이면 이 판정 대신 "원문을 확인하지 못했다"고 알린다.
   - **시즌이 끝나 가는 주제**는 그 시즌 종료일 **4주 전부터**를 말한다(예: 11월 초 이후의 가을 컬러, 2월 초 이후의 겨울 컬러). 이때는 다음 시즌 버전의 **구체적인 각도를 한 줄로** 함께 제안한다.
5. **원문 확인.** 검색 결과 요약만으로는 **근거를 확정하지 않는다.**
   - 답변의 핵심 근거 2~3개와, 쓰려는 **제품명·가격·날짜·수치**는 원문 페이지를 열어서 확인한다. (페이지 읽기 도구나 브라우저 도구가 있을 때) 트렌드 모드에서는 목록의 각 트렌드가 핵심 근거이므로 항목마다 연다.
   - 페이지 읽기 도구가 돌려주는 요약도 "원문을 열어 확인한 것"으로 친다. 검색 결과의 스니펫(요약 문장)은 그렇지 않다.
   - 열지 못했거나 열 수 없는 환경이면 해당 내용에 "검색 요약만 확인"이라고 표시한다.
   - **보조 근거**(핵심이 아닌 참고 자료)는 원문을 열지 않았다면 링크 없이 "검색 요약만 확인"이라고 적은 텍스트로만 언급해도 된다. 본문의 근거 링크는 **원문을 연 출처에만** 단다. 보조 근거를 핵심 주장의 유일한 근거로 쓰지 않는다.
   - **제품명은 원문에서 확인한 것만** 쓴다. 제품명은 있고 가격만 없으면 "가격 확인 필요"로 표시하고, 가격을 추정하거나 다른 곳의 가격을 가져다 쓰지 않는다. 요리·식품·루틴처럼 직접 해 보고 쓰는 글의 가격은 **직접 산 금액과 구입처·시점만** 쓰고(직접 산 적이 없으면 비용은 쓰지 않거나 "확인 필요"로 둔다), 그 밖의 제품 가격은 원문에서 확인한 것만 쓴다.
   - 전문가·의사의 발언은 카드에 단정문으로 쓰지 않고 "○○ 전문의는 ~라고 설명한다"처럼 **누구의 말인지** 밝힌다.
6. **출처 표기는 링크로 한다.** 원문을 연 근거는 `[매체명, 날짜](URL)` 형식의 마크다운 링크로 쓴다. 검색 도구가 링크 목록을 요구하면 답변 끝에 "출처" 목록을 붙이고, 검색 요약만 본 것은 **링크 없이** "매체명 (검색 요약만 확인)"으로 구분해 적는다.
7. 결과 마지막에 **어디까지 조사했는지**를 한 줄로 밝힌다. (예: "웹 검색 4회, 원문 열람 2건, 인스타그램은 로그인 필요로 직접 조사 못 함")

## 1단계: 키워드 리서치

키워드의 **검색 의도**(사람들이 왜 이걸 찾는지)와 **지금의 흐름**을 파악한다.

- "리서치 출처" 순서로 2~4회 조사한다: 키워드 최신 트렌드, 관련 질문·고민, 인기 해시태그, 비슷한 게시물의 접근 방식.
- 키워드가 **색상·제품·소재**(예: "뮤트 색상 제품", "겨울 식재료")이면 해당 색상·소재와 어울리는 제품 유형, 이번 시즌 흐름, 대상별 어울림(예: 피부톤, 식단, 예산)을 함께 조사한다. 구체적인 제품명·가격·출시 정보는 조사로 확인된 것만 쓰고, 기사 시점이 6개월을 넘었으면 "확인 필요"로 표시한다. 써 보지 않은 제품의 후기는 쓰지 않는다.
- 핵심 정리는 5줄 이내로 한다: 핵심 흐름 / 사람들이 궁금해하는 것 / 이미 흔한 접근 / 비어 있는 틈새 / 쓸 만한 해시태그 후보. (출처 링크와 "조사 범위" 한 줄은 이 5줄에 포함하지 않고 따로 붙인다.)
- 출처가 있는 수치나 사실에는 출처 링크와 발행 시점을 붙인다. 검색 시점을 밝힌다.
- 해시태그의 게시물 수는 확인하지 못하면 "게시물 수 확인 못 함"이라고 쓴다.

## 2단계: 주제 추천

키워드에서 **주제 5개**를 제안한다. 이미 정한 주제가 있으면 이 단계는 건너뛴다.

```
1. 주제
   - 후킹 한 줄: 표지에 들어갈 문구
   - 유형: 정보형 / 후기형 / 비교형 / 리스트형 / 가이드형 / 일상형 (references/post-types.md)
   - 카드: 권장 장수
   - 준비: 짧음 / 보통 / 김
   - 왜 지금: 이 주제가 지금 먹히는 이유 (1줄)
```

- `profile.md`의 "이미 올린 게시물"과 겹치지 않게 한다. **겹침 기준**: 같은 제품군에 같은 각도(예: "퍼스널컬러별 립 추천 3가지", "에어프라이어 레시피 3가지")이면 겹친다. 같은 색·분야라도 다른 대상이나 다른 각도(다른 부위, 질감, 비교, 활용법)면 겹치지 않는다. 이어지는 주제는 "후속편"이라고 표시한다.
- "후킹 한 줄"은 `profile.md`에 **표지 후킹 문구 말투**가 있으면 그것을, 없으면 전체 말투를 따른다. (슬라이드 본문용 말투를 후킹에 쓰지 않는다.) 말투 정보가 없으면 친근한 존댓말로 쓴다.
- 오늘 날짜에서 시즌이 거의 끝난 주제(기준은 위 "최신성 확인")는 그 사실을 "왜 지금"에 적고, 다음 시즌 버전의 구체적 각도를 함께 제안한다.
- 처음 시작하는 계정이면 준비가 짧은 주제를 앞에 둔다.
- 5개 중 최소 1개는 흔하지 않은 각도(틈새)로 낸다.
- 반복할 만한 포맷이면 "시리즈로 만들기 좋음"이라고 표시한다.
- 끝에 "어떤 주제로 갈까요?"라고 묻고 멈춘다. (질문은 이것 하나만 한다. 프로필 저장 질문은 8단계 끝으로 미룬다.)

## 3단계: 기획서

고른 주제로 **한 장짜리 기획서**를 만든다.

```
- 목표: 저장 / 공유 / 팔로우 / 댓글 / 활동 포트폴리오 중 가장 우선인 것 하나
- 타깃: 누가 보는가
- 핵심 메시지: 한 문장
- 유형과 카드 장수: 왜 이 장수인지 한 줄
- 카드 구성표: 장 / 역할 / 핵심 내용 (references/post-types.md의 구성을 바탕으로 주제에 맞게 조정)
```

카드 장수 판단 기준은 `references/post-types.md`를 따른다. 정보량이 적으면 장수를 줄이고, 억지로 채우지 않는다.

## 4단계: 카드 문구

장마다 쓴다.

- 한 장에 메시지 하나. 제목은 12자 안팎(표지 후킹만 20자 안팎), 본문은 2~3줄, 한 장당 5초 안에 읽히게 한다.
- 표지는 후킹, 마지막 장은 요약 뒤에 **행동 하나**(저장·공유·질문 중 하나)를 둔다.
- 후킹과 문구 공식은 `references/hook-caption.md`를 참고한다.
- 말투는 `profile.md`를 따른다.
- 문구를 보여 준 뒤 **멈추지 않고** 5단계로 이어간다. 수정 요청은 언제든 받는다. 5단계의 색상 질문 메시지 끝에 "문구를 고치고 싶으면 알려 주세요"를 **안내문(질문 아님)**으로 덧붙인다.

## 5단계: 디자인 방향 (포인트 색상·폰트·레이아웃)

`references/color-guide.md`의 방법으로 **색상 조합 2~3안**을 제안한다.

- 각 안: 메인(배경) / 서브 / 포인트 / 글자색의 HEX 코드, 어울리는 분위기, 폰트 느낌, 왜 이 주제에 맞는지 한 줄.
- **색은 HEX 숫자만 적지 말고 실제 색으로 보여 준다.** 글만으로는 색이 보이지 않기 때문이다. 환경에 맞게 고른다.
  1. 대화 안에 HTML·SVG를 그림으로 띄우는 도구(예: 시각화 위젯, Artifact)가 있으면 `assets/color-swatch.html`과 같은 모양(색 견본 4칸 + 견본 카드 2장 + 대비 수치)을 그 안에 바로 보여 준다. (시각화 도구는 쓰기 전에 도구 안내를 읽고, 평평한 색·글자 11px 이상 같은 규칙을 따른다. 색 칸은 HEX를 인라인 색으로 칠한다. 작성 시점에 이 방식으로 대화 안에 견본이 보이는 것을 확인했다. 환경에 따라 다를 수 있고, 보였는지 확인하지 못했다면 못 봤다고 알린다.)
  2. 없으면 `assets/color-swatch.html`을 작업 폴더에 복사해 `OPTIONS`(색 조합)와 `SAMPLE`(견본 문구)을 채우고 브라우저로 연다(macOS는 `open 파일`, Windows는 `start 파일`, Linux는 `xdg-open 파일`). 열 수 없으면 파일 경로를 알려 준다.
  3. 둘 다 안 되면 HEX와 함께 색 이름(예: 연한 베이지, 짙은 로즈)을 적고 "실제 색 견본은 보여 드리지 못했다"고 알린다.
  이 견본 보여 주기는 멈춤이 아니다. 견본을 보여 준 뒤 색 선택 질문(멈춤 ③)을 한다.
- 주제 속 색(제품 색, 계절, 퍼스널컬러, 트렌드 컬러)을 우선 반영한다. `profile.md`의 디자인 취향에 계정 고유 색이 있으면 1안은 그 색으로 하고 나머지 안은 변주로 제안한다. (색 선택 멈춤은 그대로 한다.)
- 글자와 배경의 대비가 충분한지 확인한다. 부족하면 글자색을 조정한다.
- 레이아웃 원칙: 비율은 도구의 기본을 따른다(Canva는 3:4=1080×1440, HTML 카드는 4:5=1080×1350). 4:5가 꼭 필요하다고 하면 6단계의 "4:5 변환"을 쓴다. 가장자리 여백 80px 이상, 본문 글자 40px 이상, **한 게시물 전체에서** 폰트 2종 이하, 장마다 구성 일관성.
- 색 조합을 제시한 뒤 **멈추고** 사용자가 고르기를 기다린다. 사용자가 "알아서 해줘"라고 했거나 답할 수 없는 환경이면 1안으로 진행한다고 알리고 계속한다.

## 6단계: 디자인 제작 (수정 가능하게)

결과물은 **나중에 문구와 색을 직접 고칠 수 있는 형태**로 만든다. 환경에 따라 고른다.

1. **Canva 연동 도구가 있으면 Canva를 우선 사용한다.** (도구 이름은 `mcp__<id>__create-design`처럼 앞에 접두어가 붙는다. 처음에는 ToolSearch로 `create-design`, `get-create-design-async-job`, `read-design`, `edit-design`, `export-design`, `get-export-formats`, `resize-design`을 한 번에 불러온다. 제품 이미지를 넣을 때는 `upload-asset-from-url`과 `create-upload-url`도 함께 불러온다.)
   - **만들기**: `create-design`을 `format: "Instagram Post (Portrait)"`로 호출한다. (실제 크기는 아래 "크기 주의" 참고.) `brief`에 아래를 모두 넣는다. 한 번 호출로 여러 페이지가 만들어진다.
     - 총 페이지 수와 장별 문구 (**문구는 그대로 쓰라고 명시**)
     - 5단계의 HEX 색상(배경·서브·포인트·글자), 여백·위치 규칙
     - **폰트는 이름까지 구체적으로 1~2개 지정**하고 "그 외 폰트는 쓰지 말 것"을 명시한다. (수정 도구에는 폰트를 바꾸는 기능이 없어서, 처음에 정해 두지 않으면 나중에 못 고친다. 쓸 수 있는 폰트 이름은 Canva에서 확인한다. 예: 제목 `Noto Serif KR` 또는 `Noto Sans KR`, 본문 `Noto Sans KR`.)
     - 강조할 단어와 색
   - **제품 이미지 넣기** (제품 큐레이션 모드, 또는 이미 만든 게시물에 이미지를 추가할 때): **승인받은 이미지 주소만** 쓴다. (아래 도구 인자는 도구 설명을 확인한다.)
     1. `upload-asset-from-url`(`url`은 공개 HTTPS 주소, `name`은 "브랜드_제품")로 Canva에 올리면 `media_id`가 돌아온다.
     2. 새로 만들 때는 `create-design`의 `references`(최대 10개)에 제품 순서대로 `media_id`를 넣고 `brief`에 "n장에 n번째 이미지를 넣는다"고 적는다. 제품 4개에 사진을 넣으면 4개이고, 로고까지 요청하면 8개라 10개 안에 들어간다.
     3. 이미 만든 디자인이거나 `references`로 위치가 맞지 않으면 `read-design`으로 트랜잭션을 연 뒤 `edit-design`의 `insert_fill`(`page_id`, `asset_type: image`, `asset_id`, `alt_text`, 위치·크기)로 해당 페이지에 직접 넣는다. 위치는 **글자와 겹치지 않는 빈 영역**에 둔다(작성 시점에 동작을 확인했고, 위치를 안 맞추면 글자를 가린다). 기존 이미지 칸이면 `update_fill`을 쓴다.
     4. 주소가 막혀 올라가지 않으면(`upload-asset-from-url`은 공개 주소만 가능하고, 일부 사이트는 Canva의 가져오기를 거부해 `fetch_failed`가 난다) 승인받은 범위에서 새 빈 폴더에 내려받은 뒤, `create-upload-url`로 받은 1회용 주소에 파일 내용을 그대로 POST해서 올린다(`curl -X POST -H "Content-Type: application/octet-stream" --data-binary @파일 "받은주소"`가 `{"mediaId":"..."}`를 돌려준다. 이 방법은 작성 시점에 확인했다). 사용자가 준 사진 파일도 같은 방법으로 올린다. 그래도 안 되면 그 제품만 컬러 칩으로 바꾸고 알린다.
     5. 검수 때 이미지가 맞는 제품 카드에 들어갔는지, 비율이 깨지지 않았는지, 글자를 가리지 않는지 확인한다. 이미지를 넣은 수정도 저장(`commit`) 승인 대상이다.
   - **사진 자리** (사진을 사용자가 직접 넣는 경우): `brief`에 제품 카드마다 **빈 사각형 자리**(서브 색, 안에 글자 없음)를 만들라고 적는다. 마지막에 "Canva에서 사진을 그 자리에 끌어다 놓으면 된다"고 안내한다.
   - **크기 주의**: 이 형식은 **1080×1440(3:4)**로 만들어진다(4:5인 1080×1350이 아님). 기본은 이 크기 그대로 쓰고 사용자에게 크기를 알리며, 3:4가 인스타그램에서 그대로 쓰이는지는 공식 확인이 필요하다고 덧붙인다. 4:5가 꼭 필요하다고 하면 아래 "4:5 변환"을 쓴다. 사용자가 처음부터 4:5를 말했다면 4:5가 기본인 HTML 카드로 진행하고(Canva를 원한다고 이미 말했다면 3:4로 만든 뒤 한 번만 변환한다), 이를 되묻지 않는다.
   - **기다리기**: 결과로 `job_id`와 `continuation_token`이 온다. 응답의 `wait_seconds`만큼 기다린 뒤 `get-create-design-async-job`으로 확인하고, `completed`가 될 때까지 반복한다. 매번 응답의 새 `continuation_token`을 쓴다. 보통 40~60초 걸린다.
   - **검수 (필수)**: 완료되면 `read-design`(`fields: design_metadata, design_content, thumbnails`)으로 확인한다. **Canva는 지시를 그대로 지키지 않는 일이 잦다.** 아래를 모두 점검하고 어긋난 것은 사용자에게 알린다.
     - 페이지 수와 **문구**: 글자가 바뀌지 않았는지(받침이 바뀐 사례: "옅게"→"열게", "얇은"→"얆은")
     - 불필요하게 들어간 요소(예: 표지의 페이지 번호)
     - 페이지 번호의 표기 통일(2/6 vs 2 / 6)과 숫자
     - **색**: 글자색과 포인트색이 지정한 HEX와 같은지(페이지마다 조금씩 다른 색이 들어간 적이 있다)
     - **폰트**가 2종 이하인지, 가장자리 **여백**이 80px 이상인지
     - 생성 직후에는 **1페이지 썸네일만** 있고 나머지는 "No stored thumbnail"일 수 있다. 이때는 글자 정보로 확인하고, 수정할 때 `edit-design`이 돌려주는 썸네일로 화면을 확인한다. 페이지마다 배경·프레임이 달라 보이는 "장마다 구성 일관성"은 글자 정보만으로 점검할 수 없으니, 사용자가 Canva에서 직접 보도록 알린다.
   - **순서**: 검수 → 수정(임시 상태) → **미리보기를 보여 주고 저장 승인 요청(멈춤 ④)** → `commit` → (4:5 요청 시) 변환. 8단계 점검에서 오탈자를 새로 발견하면 이 수정 단계로 돌아가고, 이미 4:5로 변환했다면 복사본에서 고친다.
   - **수정**: `read-design`에 `open_transaction: true`로 편집 트랜잭션을 열어야 요소의 `locator_id`가 나온다. `edit-design`은 **페이지마다 `page_index`를 지정해 따로 호출**하고(같은 트랜잭션에서 여러 번 가능), 글자 교체는 `find_and_replace_text`, **글자색·글자 크기는 `format_text`**, **도형 색은 `recolor_element`**, 불필요한 요소는 `delete_element`, 위치(여백)는 `position_element`로 고친다. 페이지 배경은 요소가 아니라 이미지 채움일 수 있어 색을 못 바꿀 수 있으니, 그럴 때는 사용자에게 알린다. 호출마다 돌아오는 썸네일을 이전과 비교해 의도하지 않은 변화가 없는지 본다. **글꼴(font family)을 바꾸는 기능은 없으므로** 폰트 이탈은 고칠 수 없다. 이런 이탈은 사용자에게 알리고 Canva에서 직접 바꾸도록 안내한다. 트랜잭션 저장(`commit`)은 되돌릴 수 없으므로 **미리보기를 보여 주고 사용자 승인을 받은 뒤** 한다. 승인을 받지 못하면 `cancel`로 취소해 원본을 그대로 두고 어긋난 목록만 알리며, 이때는 4:5 변환을 하지 않는다(원본의 오탈자가 복사본에 남기 때문).
   - **4:5 변환**: 사용자가 4:5를 꼭 원할 때만 한다. `resize-design`에 사용자 지정 크기(너비 1080, 높이 1350)를 준다(정확한 인자는 도구 설명 확인). 이 도구는 **새 디자인을 만들고 원본은 그대로 둔다.** 순서는 이렇다. (a) **오탈자 수정과 저장을 먼저** 끝낸다(그래야 복사본에 수정이 따라간다). (b) **변환 전에** "변환하면 무료 사용 횟수가 줄 수 있다"고 알린다(질문이 아니라 안내이고 멈추지 않는다). (c) `resize-design`을 호출한다. (d) 변환된 복사본을 `read-design`으로 크기(모든 페이지 1080×1350)와 문구를 다시 확인하고 썸네일로 배치를 본다(레이아웃이 자동으로 다시 짜여 제목 위치가 밀릴 수 있다). (e) 응답에 사용 횟수 안내(`uses_remaining` 등)가 있으면 알린다. `uses_remaining`이 0이면 "이번이 마지막 무료 변환이었고 이후 4:5 변환은 업그레이드가 필요할 수 있다. 수정은 복사본에서 직접 하세요"라고 알린다. (f) **최종본 안내**: 3:4 원본과 4:5 복사본 링크를 둘 다 알리되 **4:5 복사본이 최종본**임을 한 줄로 밝힌다.
   - **내보내기**: 사용자가 PNG나 PDF가 필요하면 `get-export-formats` 확인 후 `export-design`을 쓴다.
   - 마지막에 Canva **편집 링크 하나**를 최종본으로 알린다. (4:5 변환을 했다면 위 "최종본 안내"처럼 복사본이 최종본이다.) `create-design`과 `read-design`이 서로 다른 링크를 줄 수 있으니 `read-design`의 edit 링크로 통일하고, 보기 전용 링크는 따로 표시한다. "문구와 색은 Canva에서 바로 고치면 된다"고 안내하고, Canva 결과는 사용자가 직접 한 번 보도록 권한다.
   - **Canva 한도 초과**: `create-design` 등이 `quota_exceeded`(크레딧 한도 초과)나 비슷한 오류를 내면 Canva를 더 시도하지 않고 **같은 문구와 색으로 HTML 카드를 만든다**(아래 2번). 한도 때문에 HTML로 만들었고, 한도가 풀리면 같은 문구로 Canva에서 다시 만들 수 있다고 알린다. 되묻지 않는다.
   - 연결: 플러그인으로 들어 있는 Canva(`plugin:marketing:canva`)는 로그인 시 `Invalid redirect URI` 오류가 날 수 있다. 그럴 때는 Claude 계정의 **Canva 커넥터**(Connectors)로 연결한다.
2. **Canva가 없으면 HTML 카드로 만든다.**
   - `assets/card-template.html`을 사용자가 지정한 폴더(없으면 현재 작업 폴더 안의 `insta-cards/<주제>/`)에 복사하고, 파일 위쪽의 `PALETTE`와 `CARDS` 데이터만 수정한다. **`PALETTE`는 반드시 5단계에서 고른 색으로 바꾼다**(기본값은 예시용 베이지다).
   - 카드 종류는 `cover`(표지), `body`(번호·제목·설명), `list`(제목+항목 목록), `product`(제품 카드: 이미지 또는 컬러 칩, 브랜드, 제품명, 컬러명, 가격, 한 줄 설명), `end`(마무리+버튼 문구) 다섯 가지다. 제품 이미지는 승인받은 것만 작업 폴더의 `images/`에 내려받아 `product` 카드의 `img`에 상대 경로로 넣는다. 내려받을 수 없으면 `swatch`(근사색)로 컬러 칩을 보여 준다. `img`를 비워 두면 컬러 칩 위에 **사진 자리**(클릭하거나 파일을 끌어다 놓기)가 나오고, 사용자가 고른 사진은 컴퓨터 안에서만 처리되어 저장하는 PNG에 그대로 들어간다(작성 시점에 확인했다). 결과를 알릴 때 이 방법을 안내한다. 예: 레시피는 `cover` → `list`(재료) → `body`(순서) 여러 장 → `end`. 제목의 강조는 `<em>말</em>`, 제목 줄바꿈은 `<br>`, `body`의 설명(`sub`) 줄바꿈은 `\n`이다. 데이터를 스크립트나 도구로 파일에 쓸 때 `\n`이 실제 줄바꿈으로 바뀌어 코드가 깨지지 않게 주의한다.
   - 브라우저에서 열면 글자를 클릭해 바로 고치고, 색을 바꾸고, 카드별로 PNG로 저장할 수 있다.
   - 열어서 화면을 확인한 뒤 알린다. 확인 못 했으면 확인하지 못했다고 말한다.
3. 둘 다 안 되면 카드별 **디자인 지시서**(배경색, 글자 위치, 크기, 폰트)를 표로 준다.

Canva 도구가 없으면 **멈추지 않고** 2번(HTML 카드)으로 진행하고, 마지막에 "Canva를 연결하면 Canva에서 바로 고칠 수 있는 디자인으로 만들 수 있다"고 한 줄로 안내한다. 사용자가 Canva를 꼭 원한다고 말한 경우에는 연결 방법을 함께 안내하되, 기다리지 않고 HTML 카드로 진행한다. 연결 없이 Canva로 만든 척하지 않는다.

## 7단계: 캡션과 해시태그

`references/hook-caption.md`의 구조를 쓴다.

```
캡션: 후킹 1~2줄 + 본문 3~5줄 + 마무리 질문 또는 저장 유도
해시태그: 10개 안팎 (큰 태그 3 + 중간 4 + 작은/주제 태그 3), 1단계(또는 트렌드 모드) 조사 결과 반영
```

- 조사를 건너뛰어 해시태그 근거가 없으면 해시태그를 직접 검색해서 확인한다.
- `profile.md`에 **대외활동 규칙**(필수 해시태그, 계정 태그, 금지 표현)이 있으면 캡션과 해시태그에 반영하고 8단계에서 점검한다.

## 8단계: 업로드 점검

`references/checklist.md`로 점검한 결과를 짧게 알린다. 광고·협찬 표기, 저작권(이미지·음악·폰트), 효능 단정 표현, 오탈자, 게시 시간 제안이 들어간다.

끝내기 전에 **확인한 것과 확인하지 못한 것**을 각각 한 줄로 알린다(예: 화면으로 본 것, 못 본 것, 도구 한도로 못 한 것). 그다음 **마지막에 질문 하나만** 묻는다(멈춤 ⑤).
- `profile.md`가 있으면: "이 게시물을 '제작 완료, 업로드 전' 목록에 추가할까요?" (이미 올렸다고 하면 "올린 게시물"에 추가한다. 목록 칸이 없으면 만든다.)
- 없으면: "지금까지 알려 주신 정보로 `profile.md`를 만들어 둘까요?"라고만 묻는다. 사용자가 "예"라고 하면 위 0단계의 온보딩 질문(최대 4개, 이미 아는 것은 뺀다)을 **번호를 매긴 한 메시지**로 묻는다.
- 트렌드 질문만 하고 끝난 경우에는 묻지 않는다.

## 하지 않는 것

- 인스타그램에 자동 업로드
- 팔로워·조회수 분석
- 근거 없는 효능·수치 주장, 경험하지 않은 후기 작성
- 사용자의 로그인 정보 요구
